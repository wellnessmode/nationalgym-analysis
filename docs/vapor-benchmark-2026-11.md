# VAPOR 벤치마킹 · 우리 앱 측정 신뢰도 진단

작성 2026-11-21 · 대상 `motion-beta.html` v2.1.1-beta

표기: **확인** = 출처에서 직접 확인 / **추론** = 확인된 사실에서 논리적으로 도출 / **미확인** = 단서만 있음.
VAPOR 공식 사이트·앱스토어 본문은 이 작업 환경에서 직접 열 수 없어, VAPOR 관련 "확인"은 서로 다른 검색 결과 2건 이상에서 같은 원문이 반복된 경우를 뜻합니다.

## 1. 결론

1. **VAPOR가 정확해 보이는 이유는 더 좋은 AI가 아니라 "재는 대상"이 다르기 때문입니다.** VAPOR는 점프 높이(cm), 횟수, 버틴 시간(초), 100°대의 큰 각도를 잽니다. 우리는 어깨·골반이 1~3° 기울었는지를 잽니다. 카메라 포즈 인식의 오차는 어느 쪽이든 ±1~2°로 같은데, 103°에서 2°는 2%이고 3° 기준에서 2°는 67%입니다.
2. **우리 앱의 편차는 실측으로 확인됩니다.** 같은 사람·같은 자세 사진을 서는 위치와 거리만 바꿔 30번 넣으면 골반 기울기가 최대 1.9° 벌어지고, 폰이 ±2° 기울면 어깨 기울기가 5.2° 벌어집니다. 판정 기준은 3°입니다. 같은 사진을 좌우 반전만 해도 골반 기울기가 0.2°에서 3.7°로 바뀝니다.
3. **모델을 더 큰 것으로 바꿔도 해결되지 않습니다.** lite·full·heavy 세 모델 모두 편차가 같은 수준이고, 같은 사진에 대해 세 모델이 서로 다른 답을 냅니다.
4. **VAPOR도 검증된 제품은 아닙니다.** 직원 6명 규모, 센터용 앱 다운로드 100+, 공개된 정확도 검증 자료 없음. 대표님이 보신 게시물에는 인스타그램의 "AI 콘텐츠" 표시가 붙어 있습니다.
5. **고치는 방향은 네 가지입니다.** (가) 촬영 조건을 앱이 강제, (나) 지표를 신뢰 등급으로 나눠 작은 각도는 숫자 대신 구간으로, (다) 큰 각도·횟수·시간 중심으로 재편, (라) 재현성 테스트를 통과해야 배포. 상세는 5장.

## 3. 우리 앱 실측 — 재촬영 재현성 실험

### 3.1 방법

실제 사람의 정면 전신 사진 1장(MediaPipe 공개 테스트 사진, 검은 상의·청바지)을 세로 카메라 프레임(720×1280)에 배치하고, **자세는 그대로 둔 채** 아래 조건만 바꿔 30번씩 넣었습니다. 자세가 같으므로 참값은 변하지 않고, 값이 달라진 만큼이 전부 측정 오차입니다. 지표는 앱의 실제 `calcM()` 함수로 계산했습니다.

- B: 같은 프레이밍 + 눈에 안 보이는 수준의 센서 노이즈
- C: 재촬영 — 서는 위치 ±5%, 거리(인물 크기 72~98%), 조명 ±20%
- D: C + 폰 기울기 ±2°
- F: 라이브 추적(앱의 실시간 화면과 같은 방식) 프레임 간

실제 현장은 여기에 자세 흔들림, 옷 주름, 카메라 높이 차이, 렌즈 왜곡이 더해지므로 **아래 수치는 가장 좋은 경우의 하한**입니다. 사진 1장 기준이라 사람·옷에 따라 수치는 달라집니다. 재실행: `node tools/repeat-test/run.js`

### 3.2 결과 — 작은 각도 지표 (판정 기준 3°)

표준편차 / 범위(최대−최소), 단위 °, N=30

| 모델 | 조건 | 어깨 기울기 | 골반 기울기 | 체간 기울기 |
|---|---|---|---|---|
| lite | B 노이즈만 | 0.16 / 0.7 | 0.23 / 1.2 | 0.13 / 0.5 |
| lite | C 재촬영 | 0.35 / 1.3 | 0.41 / 1.8 | 0.22 / 0.8 |
| lite | D 재촬영+폰 ±2° | **1.41 / 3.9** | **1.51 / 5.2** | **1.38 / 4.7** |
| full | B 노이즈만 | 0.27 / 1.1 | 0.24 / 0.9 | 0.14 / 0.6 |
| full | C 재촬영 | 0.36 / 1.5 | 0.46 / 1.9 | 0.25 / 1.0 |
| full | D 재촬영+폰 ±2° | **1.44 / 5.2** | **1.21 / 4.4** | **1.36 / 4.7** |
| heavy | B 노이즈만 | 0.25 / 1.0 | 0.22 / 0.9 | 0.12 / 0.5 |
| heavy | C 재촬영 | 0.36 / 1.4 | 0.60 / 3.0 | 0.21 / 0.9 |
| heavy | D 재촬영+폰 ±2° | **1.40 / 4.4** | **1.29 / 5.0** | **1.30 / 4.2** |

읽는 법:
- 카메라가 완벽히 수평이어도(C) 골반 기울기는 1.8~3.0° 범위로 벌어집니다. 3° 기준 근처의 회원은 찍을 때마다 정상/이상이 바뀝니다.
- 폰이 ±2° 기울면(D) 범위가 4~5°가 됩니다. **폰 기울기가 지표에 그대로 더해지기 때문입니다.**
- heavy 모델이 lite보다 나은 점이 없습니다.

### 3.3 같은 사진인데 답이 다른 경우

| 실험 | 결과 |
|---|---|
| 같은 사진, 모델만 교체 | 어깨 기울기 lite −0.5° / full −1.4° / heavy −0.4°, 골반 기울기 2.2° / 1.3° / 2.7° |
| 같은 사진, 좌우 반전 후 다시 측정(full) | 골반 기울기 0.15° → 3.69°, 어깨 기울기 −1.40° → −0.45° |
| 같은 사진, 좌우 반전 후 다시 측정(heavy) | 어깨 기울기 +1.26° → −1.75° (방향이 뒤집힘) |
| 라이브 추적 vs 사진 1장(lite) | 골반 기울기 라이브 4.1° / 사진 2.2° |

원리: 포즈 모델(BlazePose)은 전신을 256×256 픽셀로 줄여서 봅니다. 이 실험의 인물 크기로 환산하면 모델이 보는 어깨 폭은 약 40픽셀, 골반 폭은 약 25픽셀입니다(추정). **골반점 하나가 1픽셀 어긋나면 약 2.3°, 어깨점은 약 1.5°가 변합니다.** 3° 기준은 모델 해상도로 1~2픽셀 차이를 판정하는 셈이고, 카메라 해상도를 올려도 이 한계는 그대로입니다.

라이브 화면이 주는 착시: 라이브 추적 중에는 프레임 간 표준편차가 0.01~0.1°로 매우 안정적으로 보입니다(F). 추적기가 이전 프레임 위치를 이어받기 때문입니다. 화면에서는 숫자가 흔들리지 않으니 정확해 보이지만, 다시 찍으면 다른 값에 고정됩니다. "화면에선 멀쩡한데 찍을 때마다 다르다"는 현장 피드백과 일치합니다.

### 3.4 대조군 — 큰 각도 지표

같은 조건, full 모델, 표준편차 / 범위

| 지표 | 평균 | C 재촬영 | D 재촬영+폰 ±2° | 값 대비 표준편차 |
|---|---|---|---|---|
| 무릎 굽힘(런지 자세) | 105.5° | 1.46 / 5.7 | 1.51 / 6.0 | 1.4% |
| 어깨 외전(팔 수평) | 94.5° | 0.71 / 2.5 | 1.45 / 6.0 | 0.8~1.5% |
| 팔꿈치 굽힘 | 69.8° | 1.09 / 4.2 | 0.87 / 3.5 | 1.6% |
| 어깨 외전(팔 내림) | 20.8° | 0.26 / 1.2 | 1.22 / 4.2 | — |
| (비교) 골반 기울기 | 1.8° | 0.46 / 1.9 | 1.21 / 4.4 | **3° 기준의 15~40%** |

무릎 굽힘과 팔 수평은 두 번째 사진(옆으로 선 런지 자세, 인물이 프레임 높이의 16%로 작게 찍힌 불리한 조건)에서 잰 값입니다.

절대 오차는 큰 각도나 작은 각도나 비슷합니다(표준편차 0.3~1.5°). 차이는 **그 오차가 판정에 미치는 영향**입니다. 105°에서 ±1.5°는 결과를 바꾸지 않지만, 3° 기준에서 ±1.5°는 판정을 뒤집습니다. VAPOR가 고른 지표와 우리가 고른 지표의 차이가 이것입니다.

### 3.5 소프트웨어 보정만으로 얼마나 줄어드나

같은 캡처 프레임을 이동·확대·좌우 반전해 8번 인식한 뒤 관절별 중앙값을 내는 방식(촬영 횟수는 그대로)을 시험했습니다. 조건 C, 표준편차:

| 모델 | 어깨 기울기 | 골반 기울기 |
|---|---|---|
| lite | 0.42 → 0.24 | 0.48 → 0.32 |
| full | 0.34 → 0.24 | 0.57 → 0.55 |
| heavy | 0.36 → 0.18 | 0.47 → 0.35 |

어깨는 30~50% 줄지만 골반은 효과가 들쭉날쭉합니다. 도움은 되지만 이것만으로 3° 판정을 믿을 수 있게 되지는 않습니다. 촬영 조건 통제와 표시 방식 변경이 함께 필요합니다.

## 4. 왜 편차가 큰가 — 코드 진단

`motion-beta.html` 전체를 측정 정확도 관점에서 감사하고, 각 항목을 별도 검증자가 코드 실행으로 다시 확인했습니다. 아래에서 "재현"은 앱의 실제 함수에 좌표·사진을 넣어 그 숫자가 나오는 것을 확인했다는 뜻입니다.

### 4.1 구조적 원인 — 모델을 바꿔도 남는 것

| # | 원인 | 근거 |
|---|---|---|
| 1 | **판정 기준이 측정 오차보다 촘촘함** | 어깨·골반·머리 기울기 정상 기준 3°. 사진 오버레이는 1.0° 넘으면 빨강, Before/After 표는 1° 변하면 개선/악화로 칠함. 체크리스트 자동 판정도 1.0° 기준. 재촬영 표준편차 0.35~0.6°는 "이보다 작은 변화는 오차와 구분 못 함"의 한계(최소검출변화)로 환산하면 1.0~1.7°, 폰 ±2°가 섞이면 3.4~4.2° |
| 2 | **폰 기울기가 각도에 그대로 더해지고 수평계는 표시만 함** | 수평계 값은 화면에만 쓰이고 촬영 차단·각도 보정·저장 어디에도 쓰이지 않음. ±2°를 파란색(정상)으로 표시하는데 이는 3° 기준의 67%. 좌우 기울기와 앞뒤 숙임이 합쳐진 값 하나만 보여 줘서 어느 쪽으로 바로잡을지도 알 수 없음. 폰 기울기 1°당 몸통 대칭 지수도 약 5.5점 상승 |
| 3 | **거리·카메라 높이·몸 방향을 재지도 막지도 않음** | 크기 조건은 하한(화면의 45%)뿐. 가이드 실루엣에 맞추면 약 1.6~1.9m, 온보딩 문구는 2.5~3m, 그런데 3m에서는 크기 조건이 "더 가까이"를 띄움(추정). 몸이 10° 돌아서 있고 카메라가 어깨보다 45cm 낮으면 그것만으로 어깨 기울기 1.8°(2.5m)~3.0°(1.5m)가 생김 |
| 4 | **점수 구조가 오차를 키움** | 3° 지표는 3.0°=100점, 3.6°부터 "관리 필요", 4.5°=0점. 0~100점 전체가 1.5° 안에 있음(재현). 가중치 105 중 62가 어깨 높이차·골반 높이차·눈 높이차·체간 편위 4개 값에서 나옴. 같은 지표가 여러 검사에 있으면 가장 나쁜 값을 채택(골반 기울기는 5개 검사) — 오차 섞인 값의 최댓값이라 항상 나쁜 쪽으로 치우침 |
| 5 | **지표 이름과 실제 계산이 다름** | "어깨 말림"은 실제로는 몸통 전후 기울기(스쿼트 상체 전경사와 같은 숫자)라 눈에 띄게 굽은 회원도 "좋은 위치"가 나옴. 몸통 대칭 지수(POTSI/ATSI)는 어깨·골반 기울기를 다시 조합한 값. 골반 기울기는 골반뼈가 아니라 옷 위에서 추정한 고관절 중심 2점. 머리 기울기는 모델 기준 7픽셀 떨어진 눈 2점 |

### 4.2 결정적 버그 — 판단 없이 고쳐야 하는 것

| # | 버그 | 증상 (재현된 값) |
|---|---|---|
| 6 | **각도를 화면 비율 보정 없이 계산** (SLR만 보정됨) | 세로 폰에서 어깨 외전 실제 160° → 147°(제한 판정), 스쿼트 상체 기울기 20° → 33°(경계)·30° → 46°(과도), 한 발 서기 골반 7° → 4°(정상). 가로 태블릿에서는 반대로 틀림. 같은 팔이 동작 패널 147° / 표 163° / 실제 160° |
| 7 | **SLR 표·게이지·종합점수가 항상 90°** | 화면 세로 잠금 상태로 폰을 눕혀 찍으면(앱이 안내하는 기본 경로) 실제 40°·60°·80° 모두 90° "정상". 동작 패널만 실제 값을 내서 한 리포트 안에서 모순. 좌우 중 잘 올라간 다리를 채택해 한쪽 제한이 사라짐 |
| 8 | **전굴 각도가 90°에서 접힘** | 깊이 숙일수록 값이 줄어듦: 실제 120° → 72°, 135° → 61°, 150° → 46°. 가장 유연한 회원이 "유연성 보강 필요"를 받음 |
| 9 | **정지 사진도 영상 추적 모드로 인식** | 같은 사진의 골반 기울기가 직전에 무엇을 처리했느냐에 따라 0.15° / 1.35° / 0.91° / 1.24°. "재분석"만 다시 눌러도 1° 넘게 바뀜. Before 직후 After를 처리하면 변화량이 왜곡됨(실제 −1.15° → −0.10°). 인식 직전에 빈 프레임을 한 번 넣으면 해결되는 것을 확인 |
| 10 | **"7프레임 중앙값"이 사실상 표본 1개** | 추적기가 이전 프레임을 이어받아 7프레임이 거의 같은 값. 독립 측정이 아니라 편차를 줄이지 못함 |
| 11 | **품질 게이트가 한 항목 실패로는 안 막힘** | 계속 움직이는 중에도 80점으로 통과해 "✓ 그대로 유지하세요"가 뜨고 자동 촬영됨. 수동 촬영·갤러리 업로드는 검사 없음 |
| 12 | **모델이 조용히 바뀌고 기록이 없음** | 한 번 크래시로 판정되면 그 기기는 계속 lite. 아이폰은 full, 메모리 4GB 미만 안드로이드는 lite. 모델 주소가 "latest"라 배포 없이 값이 바뀔 수 있음. 운영본(`index.html`)과 베타가 서로 다른 엔진. 같은 회원을 트레이너마다 다른 모델로 잴 수 있음 |
| 13 | **Before/After 점수가 서로 다른 검사 구성끼리 비교됨** | After에서 일부 검사만 다시 찍으면 측정이 그대로여도 점수가 오르내림 |
| 14 | **AI 서술이 표와 다른 계산식을 씀** | 픽셀 단위 수치, 보정 없는 각도, 세 번째 SLR 정의를 AI에 넘김. 회원이 읽는 문장의 숫자가 표와 어긋날 수 있고, 다시 누르면 내용이 바뀜 |
| 15 | **어깨 좌표를 18% 바깥으로 옮긴 값으로 측정** | 외전각이 약 3° 크게 나옴. 점 편집 시 손으로 옮긴 위치와 표시 위치가 어긋남 |

### 4.3 개발 방식의 원인

변경 내역 64개 버전·109개 커밋을 분석한 결과입니다. 이 부분은 제가 작업해 온 방식의 문제입니다.

- **정확도를 수치로 잰 적이 없습니다.** 109개 커밋 중 수정 전후 정확도를 비교한 커밋은 0건. 검증은 문법 검사, 지어낸 좌표, 화면 캡처뿐이었고 실제 카메라+포즈 인식 경로는 현장에서 처음 돌았습니다. 트레이너가 사실상 테스트 장비였습니다.
- **같은 문제가 반복됐습니다.** 64개 버전 중 SLR 관련 20개, 스켈레톤·인식 21개, 좌우·부호 뒤집힘 21개. 피드백 반영 릴리스 11회 중 8회에 SLR이 다시 등장.
- **모델과 임계값을 근거 없이 바꿨습니다.** 인식 신뢰도 0.55→0.4→0.5, 모델 lite↔full 등. 매번 "이것이 핵심 원인"이라며 바꿨지만 전후 비교가 없었고, 이번 실측에서 모델 등급은 편차와 무관했습니다.
- **경쟁 앱에 있는 기능을 먼저 넣고 나중에 뺐습니다.** CVA, Q-angle, 악화 예측, 스코리오미터 등. 선정 기준이 "이 카메라로 재현성 있게 잴 수 있는가"가 아니었습니다.
- **오차 위에 확정적 문장이 쌓였습니다.** 측정값 → 점수 → 소견 → 체형 유형 → 근육 맵 → 운동 플랜으로 이어지면서 ±1.5° 오차가 "골반 틀어짐형, 이 근육을 늘리세요"가 됐습니다.

## 5. 고치는 계획

원칙: 지표를 먼저 고치지 않고 **재는 도구부터** 만듭니다. 각 단계는 숫자로 된 통과 기준이 있고, 통과하지 못하면 배포하지 않습니다.

### 0단계 — 측정 관문

- `tools/repeat-test`를 앱의 실제 경로(사진 인식, 촬영, 동작 분석, SLR)까지 확장
- 불변성 테스트: 같은 사진 10회 = 같은 값 / 좌우 반전 = 부호만 반대 / 세로·가로 프레임 = 같은 각도 / 폰 눕힘 SLR = 실제 각도
- 지표별 통과 기준 정의: 재촬영 표준편차와 최소검출변화
- **필요한 것**: 실제 기기로 찍은 사진·영상. 직원 5~10명, 검사별로 자세를 풀었다 다시 서서 3회씩. 이것이 있어야 합성 실험이 아닌 현장 편차를 잴 수 있습니다

### 1단계 — 결정적 버그 수정

4.2의 6~15번. 화면 비율 보정을 공용 각도 함수 하나로 통일, SLR 정의 단일화, 전굴 접힘 수정, 정지 사진 인식 전 추적 초기화, 최댓값 집계 제거, Before/After 짝 비교, 모델 버전 고정과 기록, AI 입력을 표의 값으로 통일.
통과 기준: 0단계 불변성 테스트 전부 통과.

### 2단계 — 촬영 조건 강제

- 거치 모드: 흔들림 센서로 손 촬영을 감지해 거치를 요구, 손 촬영 결과는 "참고용"으로 표시
- 폰 좌우 기울기와 앞뒤 숙임을 따로 측정, 좌우 기울기는 좌표를 반대로 돌려 보정, ±3° 밖이면 촬영 차단
- 목표 거리 하나로 통일(인물 높이 60~70%, 중앙) — 실루엣·안내 문구·게이트가 같은 값을 쓰도록
- 필수 조건을 전부 통과해야 촬영(점수 합산 폐지), 실패 사유를 한 번에 하나씩 음성으로 안내
- 한 번 촬영에 여러 번 독립 인식해 중앙값과 흩어짐을 함께 저장, 흩어짐이 크면 재촬영 요구
- After 촬영 때 Before 스켈레톤을 반투명으로 띄워 같은 위치에 서게 함
- 촬영 조건(기울기, 거리, 모델, 자동/수동)을 사진과 함께 저장

통과 기준: 조건 D(폰 ±2°)의 어깨 기울기 범위가 조건 C 수준(1.5° 이하)으로 내려올 것.

### 3단계 — 지표와 점수 재설계

- 4.4 표대로 지표를 세 등급으로: 숫자로 표시 / 구간으로 표시 / 제외
- 작은 각도는 "수평 범위 · 경계 · 뚜렷" 3단계와 오차 범위로 표시, 1° 색칠 제거
- Before/After는 최소검출변화를 넘을 때만 "개선"으로 표기, 그 이하는 "변화 없음(오차 범위)"
- 종합 점수는 숫자 등급 지표 중심으로 재구성, 중복 지표 제거
- 근육 맵·운동 플랜은 숫자 등급 지표와 트레이너 체크리스트에서만 나오게

통과 기준: 재촬영 30회에서 판정(정상/경계/뚜렷)이 바뀌는 비율 5% 이하.

### 4단계 — 큰 값 중심으로 종목 재편

- 화면을 종목 단위로: 종목마다 촬영 방향 하나, 핵심 숫자 하나와 게이지, 시도 횟수 표시
- 이미 있는 것을 전면으로: SLR, 어깨 외전, 전굴, 오버헤드 스쿼트 깊이·무릎 모임
- 추가 후보: 한 발 서기 유지 시간, 스쿼트·런지 횟수, 좌전굴 접힘 각도, 코어 유지 시간
- 점프는 60fps 이상이 필요해 후순위
- 종목별 판정 로직과 실제 영상 표본을 따로 관리, 새 종목은 "베타" 표시로 출시

### 5단계 — 현장 검증과 공개

회원 20명 이상을 같은 날 2회 측정해 지표별 재현성 수치를 내고 방법론 페이지에 공개. VAPOR를 포함해 조사한 경쟁 앱 중 이 수치를 공개한 곳은 찾지 못했습니다.

## 부록

### A. 미확인 항목

- VAPOR "17가지 종목"의 정확한 목록, Business Package 금액
- VAPOR Body Scan의 방식·출력 단위·정확도 — 우리 앱과 직접 겹치는 유일한 종목
- VAPOR의 포즈 모델, cm 환산 방식, 특허 청구항
- VAPOR의 실제 반복 측정 편차 — 데모를 받아 같은 사람을 반복 측정해 보는 것이 가장 확실
- 측정 문헌의 구체 수치(사진 계측 재현성, 포즈 모델 대 모션캡처 오차) — 이번 작업에서 논문 원문에 접근하지 못해 싣지 않음
- 우리 앱의 실제 현장 편차 — 3장은 같은 사진을 재배치한 합성 실험이라 하한값

- expersinc.com, bewinnar.com, 앱스토어, 유튜브, 인스타그램 본문은 이 작업 환경에서 열 수 없었음. VAPOR 관련 내용은 검색 결과에 인용된 공식 페이지·스토어 원문을 교차 확인한 것
- 인스타그램 게시물은 대표님이 보내주신 캡처 2장만 확인

- 4.4 지표별 판정 중 일부(전굴 접힘, 몸통 대칭 지수 수치, 지표별 오탐률 추정)는 감사자 1명의 실행 결과이며 독립 재검증이 진행 중
